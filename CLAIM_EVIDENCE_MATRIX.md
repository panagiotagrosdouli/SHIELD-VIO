# Claim–Evidence Matrix

## Purpose

This matrix is the authoritative link between paper language, executable experiments, stored artifacts, and claim boundaries. A claim remains **planned** until every required artifact is generated by the declared command. Passing unit tests establishes software behavior, not empirical confirmation of a research hypothesis.

## Evidence artifact contract

Each confirmatory claim must resolve to these artifact layers:

1. **Input registry:** dataset, sequence, license/source URL, index checksum, calibration checksum.
2. **Estimator output:** timestamped pose, validity, covariance when available, innovations/residuals when available, visual statistics, tracking/reset/relocalization events, and latency.
3. **Label table:** observable criteria, threshold version, persistence, onset, event ID, and future targets for each horizon.
4. **Feature table:** causal feature timestamp, source timestamp range, missingness flags, schema version, and explicit exclusion of privileged fields.
5. **Prediction table:** raw scores, calibrated probabilities, bounds, shift state, threshold, action, split, and method version.
6. **Run metrics:** frame- and event-level endpoints with denominators and duration.
7. **Aggregate inference:** grouped bootstrap sources, paired differences, confidence intervals, effect sizes, and corrected exploratory p-values.
8. **Decision results:** policy transitions, intervention reason, unsafe exposure, mission status, recovery, cost setting, and utility.
9. **Manifest:** commit, dirty state, command, environment, configuration hash, seed, all artifact hashes, and completion status.

## Evidence labels used in prose and figures

Every table, figure, and result paragraph must use exactly one label:

- `ANALYTICAL_OR_UNIT`
- `SYNTHETIC`
- `PUBLIC_DATASET_SMOKE`
- `PUBLIC_DATASET_EVALUATION`
- `CLOSED_LOOP_SIMULATION`
- `PHYSICAL_ROBOT`

Mixed panels must label each trace or subpanel. Evidence levels are not cumulative: a public-data input with a synthetic controller is not physical validation.

## Unsupported-claim register

The following statements are prohibited until the specified gate is met:

| Prohibited statement | Gate required before use |
|---|---|
| “SHIELD-VIO improves safety.” | C5 closed-loop paired comparison with uncertainty and completion trade-off |
| “The probabilities are calibrated.” | Disjoint calibration fit and held-out reliability results, with dataset/split named |
| “The method handles domain shift.” | C4 unseen-condition results showing discrimination, calibration, coverage, and policy effects |
| “The method generalizes across VIO estimators.” | At least one established external backend plus reduced-input comparison |
| “Real-time.” | Measured latency distribution on named hardware, including feature extraction and estimator overhead |
| “Robust.” | Named perturbations, severities, datasets, baselines, and uncertainty intervals |
| “State of the art.” | Contemporary methods executed under the same protocol; not an intended paper claim |
| “Safe”, “certified”, or “guaranteed.” | Outside the intended claim boundary; empirical risk reduction is not a formal guarantee |
| “Validated on ROS 2/hardware.” | Stored executable ROS 2 or physical-robot artifacts, respectively |

## Acceptance rule for manuscript numbers

A manuscript placeholder may be replaced only when a generation script reads a completed, checksum-verified aggregate artifact. Hand-copied values and manually edited tables are not accepted. Failed, partial, exploratory, or dirty-tree runs remain visible in the artifact index but are excluded from confirmatory tables.
